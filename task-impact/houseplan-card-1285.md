# #1285 — HA E2E: надо, дополнить существующее путешествие

Источник: https://github.com/Matysh/houseplan-card/issues/1285.
Принятый source SHA: ff650ec58838a85767e15fbb5de9193c336f9034.

Генератор нашёл необходимое продуктовое исправление: законный зависимый T на
решёточной диагональной опоре нельзя независимо округлять, снимать dependency
и изгибать опору только по числовому предложению Optimize. В существующем
editor/Optimize journey нарисовать T на диагонали, сохранить точный q и dependency
через настоящий config/get, открыть Optimize и убедиться, что изменений и записи
нет. Проверить reload/Undo. Для legacy-импорта сохраняется прежний явный Align;
независимые off-grid вершины по-прежнему дают осмысленную работу Optimize.
Добавить контроль уже автомигрированного писателем старого плана: нерешёточный
T на точной горизонтальной/вертикальной опоре выравнивается вдоль опоры с
сохранением зависимости, без наклона ветви; следующий Optimize уже no-op.
Признак modelVersion=11 сам по себе не означает происхождение «с нуля».

Сам seeded механизм (валидность, проекции, no-op и сокращение replay) остаётся
адресным unit-контролем. Перенос 210 геометрических +210 paired последовательностей
целиком в HA дублировал бы модельную проверку. Нового mandatory gate обычных задач нет.

Сквозная проверка настоящих жестов, серверного сохранения, reload/Undo и диалога
учтена отдельно в task-impact/houseplan-card-1282.md, -1283.md и -1284.md.
По обновлённому решению владельца инвариант также проверяет layout после
удаления комнаты/поглощения Merge, пространства и устройства (#1287), включая
перемещённые подписи и позиции; отдельные исходные fixtures и seeded pair replay
не заменяют сквозной путь. Для #1287 он записан в houseplan-card-1287.md.
Импорты/legacy/manual JSON/stale client, позиции с неподтверждённым владельцем
и физическая полнота fail-closed перекрытий остаются исключениями. Не выдавать
этот unit-прогон за real HA E2E PASS.

Перед beta.5 расширен существующий фиксированный first-space journey: настоящий
Draw диагональной опоры и on-edge T, exact q/dependency в server config/get и
экспорте; диалог Optimize сообщает no-op без config/layout revision changes,
затем reload сохраняет граф. Код: tests/lib/beta5-maintenance.mjs. Это описание
добавленного сценария, его фактический результат будет в отчёте прогона beta.5.
Остальные адресные границы выше не выдаются за уже выполненный browser E2E.

Адресный повтор first-run на исходном подготовленном ZIP beta.5 (source d33a8e42c)
в изолированном HA2026.10.4 дал2/2 PASS без skip, включая native q-T и Optimize
без config/layout записи. Лаборатория hp-e2e-first-run-dWMSfy; решение исходного
ошибочного precondition — явный desktop viewport2000×1100 и видимая фигура45px,
без изменения пользовательской камеры, координат или обхода assertions.
Это локальная диагностика; окончательный повтор beta-набора закрепит новый SHA
companion и свой полный отчёт. На CI1 прежняя сцена не поместилась до первого жеста.
