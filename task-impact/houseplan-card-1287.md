# #1287 — HA E2E: надо

Источник: https://github.com/Matysh/houseplan-card/issues/1287.
Принятый product SHA: a51c3432653e84a990e0cc74d1bf39ccb0bebe70.

Дополнить существующий editor/delete journey: передвинуть подпись комнаты и
устройства, удалить комнату/выполнить Merge и прочитать настоящий config/get и
layout/get. Запись удалённой/поглощённой подписи уходит вместе с конфигурацией;
Undo возвращает нужную пару. Удаление пространства проверить в обоих разрешённых
режимах, с исходным отказом при живых зависимостях; все его позиции уходят,
позиции другого пространства сохраняются. Удаление виртуального устройства и
обычного HA-устройства оставляет соответственно удалённый marker и минимальный
tombstone без старой позиции. Undo, reload и Optimize не находят новых сирот.

С устройствами сохранить синтетический PDF: пока Undo жив, восстановление
возвращает доступ к файлу. После следующего обычного действия/замены Undo
предыдущее удаление уже не восстанавливается, а освобождённые pins не оставляют
файл навсегда. Удаление с активной ссылкой другого устройства файл сохраняет;
отказ замены Undo не должен удалять защищённый PDF или менять исходную пару.
Фактический unlink проверяется адресным real HA backend harness; одного HTTP
404 после удаления marker недостаточно, чтобы доказать очистку диска.
Если следующим действием удаляется другое устройство с общей ссылкой на тот же
PDF, его ещё регистрируемый history-command должен защитить файл; Undo этого
удаления возвращает рабочую ссылку. Не путать этот pin с бессрочным сохранением
любого файла, встречавшегося в прежней конфигурации.

Тестировать серверную атомарность и историю, а не только локальное удаление
ключей из объекта. Импортированные/unverified записи сохраняют прежнее поведение
Optimize. Быстрый seeded pair replay #1285 не является real HA E2E PASS.
Этот сквозной сценарий ещё не выполнялся; учесть перед следующей разрешённой бетой.
